1Services and how they talk

Seven runtime pieces. Redis is the only bus: nothing calls another service directly except the video path (camera → MediaMTX → detector) and MinIO uploads (OCR → MinIO).

2Startup — what happens when containers come up

Each service starts independently and waits for Redis. Nothing starts processing frames until a camera is activated (or the saved ledger of active cameras is replayed).

3Camera lifecycle — register, activate, offline, restart

Camera configuration and the on/off command arrive through Redis. The "active" decision is stored first (a durable ledger), so a crash or reboot resumes exactly the same set of cameras.

E. Cadence and capacity (CPU)

  • Capacity calibration (engine 0, at startup): measures the loop time for 1, 2, 3 … 12 cameras (3 warm-up + 20 timed rounds, p95), budget detect_every × 1000 / 25 fps × 0.7 = 28 ms at one camera; stops after 2 consecutive misses. Stored in plate:internal:detector:capacity and /health.
  • Auto-degrade (CAPACITY_AUTO_DEGRADE=true): when cameras exceed capacity, the detection interval per camera is computed from the measurements (not fixed steps), never below DETECT_EVERY_N_FRAMES = 1, never slower than 8 fps (DETECT_MIN_FPS). Frames in between are "coasted" (no inference, tracker not updated). Logged as 🐢 lowered / 🐇 raised.
  • Missed frames: the reader keeps only the newest frame; frames replaced before the loop reached them are counted as missed in the [PERF] line. Coasted frames are separate (deliberately skipped).
  • Engine placement: pick the engine with the fewest cameras; start a new engine when full (GPU 6, CPU 16). Rebalance check every 30 s.

6OCR worker — one task

A task is one batch of up to 5 crops of the same track plus one frame. A worker handles one task at a time; three workers run in parallel by default.

How a plate is decided

Vote
  • Only valid results count (valid OCR, text not empty / "0"). Each candidate plate scores the sum of its confidences; highest sum wins (tie → highest single confidence). The best single result of the winner supplies the images.
  • No valid result: the most confident attempt is shown (raw_text), is_valid=false, plate "0".
  • At most 50 results are kept per track.
"Satisfied" (stop asking OCR)
  • winner's best confidence ≥ 0.85, or
  • ≥ 3 valid results agree and there is only one candidate.
  • When satisfied: all waiting triggers publish at once, the detector stops sending crops for this track and skips the leave-scene OCR pass.
What the backend receives (plate:vehicle:results)
  • update_type = cross_line / stop_roi — once per event per track, with the event detail (direction, stop duration …).
  • update_type = leave_scene, is_final=true — one final per track (gate: seen ≥ 8 frames and ≥ 1 crop, unless something was already published for the track).
  • Periodic re-queries are not published as records; they only feed the vote.
  • Each record carries resolved (plate, confidence, votes, image paths), ocr_results per stage, revision, complete, missing_tasks.

9Images — how many, where, what size class

Numbers are per track and per OCR task.

In the detector (memory only)
  • ≤ 5 crops per live track (DEFAULT_N_BEST_CROPS): the plate bounding box cut from the ROI frame. Ranked by (int(det_conf × 100), pixel area); a better candidate replaces the worst.
  • 1 best frame per track: a copy of the ROI frame at the moment the best crop improved.
  • Everything is dropped when the track ends.
Detector → Redis (one OCR task)
  • Up to 5 crop JPEGs + 1 frame JPEG (cv2.imencode('.jpg'), default quality 95), pickled into one value pushed to ocr:tasks.
  • Tasks per track: one per trigger (cross_line, stop_roi), one per periodic request, one leave_scene at the end. Only one task is in flight per track, and a crop set identical to the last one is never re-sent.
OCR → MinIO (one task)
  • 2 PNG uploads per task, valid or not: the first (best) crop, and the best frame.
  • Keys: valid → dynamics/ValidPlateImage/vp_<cam>_<date>_<time>.png and dynamics/ValidVehicleImage/vf_…; invalid → InvalidPlateImage/ip_… and InvalidVehicleImage/if_…. Bucket: private.
  • Model input sizes: car plate 256×64, motorcycle 240×200.
What the backend gets
  • No image bytes in Redis results — only the MinIO paths (plate_image, frame_image) of the winning result, per record and per stage in track_paths.
  • A track that needs k tasks leaves 2k objects in MinIO; there is no cleanup in this code.
  • Debug only (off by default): annotated video in ./debug_video, submission montages (max 200 files), OCR decision montages (max 200).
